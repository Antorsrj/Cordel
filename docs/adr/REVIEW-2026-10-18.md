## Cross-ADR findings

1. **No first-test ADR is Done.** Four mandatory server designs remain Proposed: 006, 007, 009, and 011. A percentage in the documentation overview does not waive those owner decisions.
2. **The deployed VM is behind the source branch.** ADR-003 source passed disposable checks, while the VM still runs the ADR-002 admin-grant binary with migrations `1,2`. Live role changes and moderation have not been proved there.
3. **Media admission and revocation are separate gates.** Server 005 needs real two-network voice/share evidence. Server 006 additionally needs strict denial of previously issued LiveKit tokens after moderation.
4. **Recovery is the real-user gate.** The owner skipped backup/restore only for the initially empty Azure test database. Disposable accounts now exist, so this exception cannot support a real-user invitation or a Server 007 completion claim.
5. **Client feasibility is still open.** Shared state checks do not prove the provisional Linux UI, capture path, detached share window, or browser client. Slint remains a candidate pending Client 101 and 106 package evidence.
6. **Final-release claims are separate.** Server 008 and Client 105 remain Proposed; macOS and Windows have their own OS evidence gates. The first test cannot be described as E2EE or cross-platform support.

The review corrected stale statements in the architecture, ADR index, workstream map, and ADR-106. The [status ledger](STATUS.md) remains the authoritative place to add future completion evidence.
