# Cordel client state recovery (ADR-102)

Library for [ADR-102](../../docs/adr/client/ADR-102-client-state-recovery.md). Chat events come from the shared [protocol crate](../../protocol/README.md). It reconciles chat after a dropped socket and decides when a reconnect may retry. Screen capture, microphones, and speakers stay in the ADR-103 adapters.

The refresh credential is the only secret this crate will persist. Access tokens and LiveKit tokens stay in `VolatileTokens`. A transport drop clears the access token and keeps the LiveKit token so the media SDK can try its own resume. A full media reconnect or a room-generation change clears the LiveKit token; the next join has to ask Axum for a new one. A kick or ban clears the refresh credential and stops catch-up.

`MemoryRefreshStore` is the test double. The operating system credential store is behind the `secret-service` feature and uses the desktop keyring service name `cordel`. The keyring crate has no default backend, so each platform names its own: the D-Bus Secret Service on Linux, the Keychain on macOS, and the Credential Manager on Windows. `OsRefreshStore` prefers that store and falls back to memory when the desktop secret service cannot be reached, which is the case in a headless session. It reports which one it got, so a client never promises a session that a restart would lose.

`IdentityClient` implements the native ADR-002 login, refresh, `/v1/me`, logout, and own-password Management Mode unlock/lock flow against the shared contract. The admin grant is held only in `IdentityClient` memory. It clears on lock, login, refresh, logout, denied `/v1/me`, and restart, and expires locally after the server's absolute lifetime. An embedding UI must never persist or log it. `NativeHttpsTransport` accepts only a bare HTTPS origin, validates TLS, disables redirects, caps responses, and must run on a worker thread; the `local-smoke` feature adds a plain `http` constructor for a disposable local server. An embedding client supplies a `RefreshStore`; it must enable the OS credential-store adapter in packaged builds. The refresh flow removes the old durable credential before sending it. If the response is lost or the server returns an error, the user must log in again; retrying the old token would revoke the session. Logout clears local credentials even if the remote response is lost.

The native transport has no bundled Cordel account or fixture credentials. The isolated transport tests use the same `docs/contracts/fixtures/v1` session and `/v1/me` examples as the server-side handoff. The actual VM endpoint passed an isolated Cloud Shell login/`me`/refresh/logout smoke test on 2026-10-18. Secret Service integration, UI wiring, and broader network recovery remain separate verification steps.

The account-bound Management Mode seam passed isolated Cloud Shell Rust 1.99.1 checks on 2026-10-18: 12 shared protocol tests, 25 client state tests, Clippy with `-D warnings`, and client/example builds. The grant stays in memory, uses a separate bearer for lock, and clears locally even if remote revocation fails. The grant API is deployed to the Azure VM and passed a focused live smoke test driven by a separate Python script. A provisional Phase 0 UI calls the native `IdentityClient` grant flow. The combined client passed [Linux CI formatting, Clippy, tests, and a release build](https://github.com/Antorsrj/Cordel/actions/runs/39519166545) on 2026-10-20; the UI has not been run interactively or exercised against Azure. The later review-source check passed 26 client-state tests, including live chat gap handling.

`MediaAdmissionClient` fetches the ADR-005 voice admission: one scoped room credential for one voice channel, with the current app access token. The server decides what the account may join; the client never receives the LiveKit API secret. A refused admission names a stable reason, so an expired session, a moderated account, and an unknown channel are told apart.

`LiveSession` implements the ADR-004 client seam. It connects, waits for `ready`, subscribes to open channels, applies `subscribed`/`message`/`lagged`/`ack`/`error` frames, and stops on `access_revoked` with `AccessBlock::Revoked`. It buffers live events while fetching every history page after the current cursor, deduplicates by `(channel_id, seq)`, reconciles open channels for a committed message whose publish was lost, and retries outbox entries with their stable `client_message_id`. `NativeLiveTransport` performs a blocking WSS upgrade with the access token in the handshake header; `NativeChatTransport` performs blocking HTTPS history and send calls. Both reject redirects and non-HTTPS production origins, and both belong on a worker thread. `LiveSession::set_read_timeout` shortens the socket read deadline for an interactive client; a read timeout is reported as `LiveTransportError::Timeout` and is not a dropped socket, so it never schedules a reconnect. `AppliedEvent` keeps the `author_id` the server puts in the event's extra fields. The `local-smoke` feature exposes plain `ws`/`http` constructors only for the server-side integration test; it must not be enabled in a shipped client. The shared native fixtures are in [docs/contracts/fixtures/native](../../docs/contracts/fixtures/native/README.md); they freeze the current `v`/`kind` subset, not the rich-content or browser target.

The live and transport tests passed on 2026-10-21: 49 client-state tests and 16 protocol tests with Rust 1.98.1, including out-of-order and duplicate application, `lagged` recovery, history pagination, revocation, transport backoff/resume, unauthorized/forbidden/server-error handling, reconciliation, stable-id send retry, a read timeout that keeps the session connected, and loopback WebSocket/HTTP checks of the native transports. The server-side ignored `disposable_database_native_client_flow` also drove these transports and `LiveSession` against the real Axum router through subscribe, send, live delivery, an offline commit, and reconnect catch-up. Clippy with `-D warnings` passed. A forced socket-level broadcast lag is not deterministic in the integration flow; the server unit tests prove lag detection and frame construction, and the client fixture test proves recovery. The Phase 0 chat worker now drives this session from the desktop shell and passed an opt-in local test against a running Axum server; an interactive two-process desktop check, the OS credential-store adapter, and network-switch checks remain separate verification steps.

The reviewed standalone identity API is deployed. `cargo run --manifest-path client/state/Cargo.toml --example identity_smoke -- https://<approved-origin>/ <disposable-login>` can repeat the login, `/v1/me`, refresh rotation, and logout check from a separate machine with a disposable account. It prompts for the password without echoing it and prints no token. It uses an in-memory refresh store intentionally; it is an isolated network proof, not a packaged client credential-store check.
